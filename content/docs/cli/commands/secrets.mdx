---
title: Secrets
description: Pull, push, run, inspect and roll back the secrets of an environment.
---

These commands work on the project of the current folder. With `GITGONE_TOKEN` set, `pull` and `run` read the environment of the token instead, without a session, a linked folder or a password ([Use GitGone in CI](/docs/cli/guides/ci)). The environment comes from `-e`, then from `.gitgone`, then a question (see [Choosing the environment](/docs/cli/concepts#choosing-the-environment)). Commands that decrypt secrets ask for your vault password, or read `GITGONE_PASSWORD`.

## `pull`

Downloads and decrypts the latest version into `.env`. If your local file differs, the CLI lists the variables that would be added, changed or removed (names only) and asks before overwriting it.

```bash
gitgone pull [OPTIONS]
```

| Option | Description | Default |
|---|---|---|
| `-e, --env <name>` | Environment to pull. | from `.gitgone`, then asked |
| `-y, --yes` | Overwrite `.env` without asking. | `false` |

If the environment has no secrets yet, a `.env` is created when there is none, and your existing file is left untouched.

**Example**

```bash
gitgone pull -e staging
```

## `push`

Encrypts `.env` and sends it as a new version. The CLI first lists the variables you added, changed or removed (names only) and asks for confirmation. Nothing is sent if nothing changed. Pushing to a new environment creates it with a key of its own.

```bash
gitgone push [OPTIONS]
```

| Option | Description | Default |
|---|---|---|
| `-e, --env <name>` | Environment to push to. | from `.gitgone`, then asked |
| `-y, --yes` | Push without asking. | `false` |

If the environment still shares the project key, the CLI offers to give it its own key (`gitgone env rotate`).

**Example**

```bash
gitgone push -e production --yes
```

## `run`

Runs a command with the secrets in its environment, without writing them to disk. If the project allows it and a `.env` exists, its values are used; otherwise the secrets are fetched from the server.

```bash
gitgone run [OPTIONS] -- COMMAND
```

| Option | Description | Default |
|---|---|---|
| `-e, --env <name>` | Environment to fetch when there is no `.env`. | from `.gitgone`, then asked |

Put the command after `--` so that its own options are not read by the CLI. `gitgone run` exits with the exit code of the command.

**Example**

```bash
gitgone run -e production -- node server.js
```

## `history`

Lists the versions of an environment, with their date and author.

```bash
gitgone history [OPTIONS]
```

| Option | Description | Default |
|---|---|---|
| `-e, --env <name>` | Environment. | from `.gitgone`, then asked |

**Example**

```bash
gitgone history -e production
```

## `log`

Shows the history of every environment of the project as a graph, like `git log --graph`: one column per environment, the newest versions first, rollbacks and key rotations. Under each version, the names of the keys it added (`+`), changed (`~`) or removed (`-`). Values are never shown.

```bash
gitgone log [OPTIONS]
```

| Option | Description | Default |
|---|---|---|
| `-e, --env <name>` | Only show this environment. | all the environments you can see |
| `--limit <count>` | Number of versions to show (1 to 500). | `20` |

```text
  ●    production v4  current  ↺ rollback to v2  alice@acme.com · 3 minutes ago
  │      ~ DATABASE_URL  - FEATURE_X
  │ ●  staging v3  current  alice@acme.com · 40 minutes ago
  │ │    + STRIPE_KEY
──┼─┼  key rotated (v2)  bob@acme.com · 1 hour ago
  ● │  production v3  alice@acme.com · 2 hours ago
```

Showing the changed keys decrypts each version, so the command asks for your vault password. A version you cannot decrypt shows `content not accessible`. Environments whose history you cannot read are left out.

**Example**

```bash
gitgone log -e production --limit 50
```

## `rollback`

Restores a previous version: it becomes the latest version on the server, and your `.env` is updated.

```bash
gitgone rollback [OPTIONS]
```

| Option | Description | Default |
|---|---|---|
| `-e, --env <name>` | Environment. | from `.gitgone`, then asked |
| `--to <version>` | Version to restore, e.g. `4` or `v4`. | asked in a list |
| `-y, --yes` | Restore without asking. | `false` |

**Example**

```bash
gitgone rollback -e production --to 4 --yes
```
