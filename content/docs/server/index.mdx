The GitGone server is the API your team's CLIs talk to. It stores the encrypted secrets, the users, teams and roles, and the audit log. It is open source under the MIT license and ships as a Docker image.

## What the server knows, and what it doesn't

| The server stores | The server never has |
|---|---|
| Encrypted versions of your secrets | Any secret value |
| Project and environment keys, encrypted for each member | A usable project or environment key |
| Each user's private key, inside a vault encrypted with a key derived from their password | Passwords, or the key that opens a vault |
| Users, teams, roles and who has access to what | |
| The audit log | |

Every action is checked by the server against the roles of the user, down to the environment. Encryption and decryption only happen in the CLI. See [Architecture & Security](/docs/architecture).

## What runs

- **The server** (`ghcr.io/project-gitgone/server`), a Node.js API listening on port `3333`.
- **PostgreSQL**, its only dependency.

There is no web dashboard on a self-hosted server: everything is done with the [CLI](/docs/cli). GitGone Cloud adds a web console on top of the same server.

## Requirements

- A machine with **Docker** and Docker Compose.
- A **domain name and HTTPS** if your team reaches it over the internet. See [Domain and HTTPS](/docs/server/domain).
