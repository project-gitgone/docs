---
title: Install with Docker
description: Run your own GitGone server in about five minutes.
---

<Steps>
<Step>
### Create a folder

```bash
mkdir gitgone && cd gitgone
```
</Step>

<Step>
### Write the secrets

Create a `.env` file with generated values instead of typing them:

```bash
echo "APP_KEY=$(openssl rand -hex 32)" > .env
echo "DB_PASSWORD=$(openssl rand -hex 24)" >> .env
echo "APP_URL=https://gitgone.example.com" >> .env
```

`APP_KEY` signs the sessions of the server and `DB_PASSWORD` protects the database. `APP_URL` is the address your team will use. Keep this file private and back it up.
</Step>

<Step>
### Write docker-compose.yml

```yaml title="docker-compose.yml"
services:
  db:
    image: postgres:16-alpine
    restart: always
    environment:
      POSTGRES_USER: gitgone
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: gitgone
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U gitgone -d gitgone"]
      interval: 10s
      timeout: 5s
      retries: 5

  app:
    image: ghcr.io/project-gitgone/server:latest
    restart: always
    depends_on:
      db:
        condition: service_healthy
    ports:
      - "3333:3333"
    environment:
      NODE_ENV: production
      HOST: 0.0.0.0
      PORT: 3333
      LOG_LEVEL: info
      APP_KEY: ${APP_KEY}
      APP_URL: ${APP_URL}
      DB_HOST: db
      DB_PORT: 5432
      DB_USER: gitgone
      DB_PASSWORD: ${DB_PASSWORD}
      DB_DATABASE: gitgone
      ALLOW_LEGACY_CLIENTS: "false"
      ALLOW_LEGACY_TOKENS: "false"

volumes:
  pgdata:
```

`ALLOW_LEGACY_*` refuse clients and tokens from before the current encryption protocol, which a new server does not need. Every setting is described in [Configuration](/docs/server/configuration).
</Step>

<Step>
### Start it

```bash
docker compose up -d
docker compose logs -f app
```

The server applies its database migrations, then listens on port `3333`.
</Step>

<Step>
### Check it

```bash
curl http://localhost:3333/healthcheck
```

```json
{ "status": "ok", "timestamp": "…", "initialized": false }
```

`initialized: false` means no administrator exists yet. Opening `http://localhost:3333` in a browser shows a status page with the next step.
</Step>

<Step>
### Create the administrator

From your machine, with the [CLI](/docs/cli/setup) installed:

```bash
gitgone login --server http://localhost:3333
```

As long as the server has no administrator, this command creates yours: enter your email, name and password. Your keys are generated on your machine, and your password never leaves it.
</Step>
</Steps>

<Callout type="warn">
  Before your team uses the server over a network, put it behind HTTPS: see [Domain and HTTPS](/docs/server/domain). Then remove the `ports` section, so that only the reverse proxy reaches the server.
</Callout>
